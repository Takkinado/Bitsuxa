# Спортклуб «БИЦУХА» — сайт продажи абонементов (Flask + Microsoft Access)

База данных — **Microsoft Access** (`data/Спортклуб.accdb`), подключение через ODBC (pyodbc).
Работает на **Windows** с Microsoft Access или бесплатным
[Access Database Engine](https://www.microsoft.com/download/details.aspx?id=54920).
Разрядность Python и Access/ACE должна совпадать (обычно обе 64-битные).

## Запуск
```bash
pip install -r requirements.txt
python check_access.py     # только если база уже готова: сверяет таблицы и типы полей
python init_access.py      # создаёт недостающее (файл, таблицы) и добавляет демо-данные в пустую базу
python app.py              # сайт: http://127.0.0.1:5000
```
Или просто дважды щёлкните `ЗАПУСК.bat` — он сам выберет Python, поставит библиотеки, проверит базу и откроет сайт.

## Что умеет сайт
**Посетитель:** главная (залы, тарифы, расписание, тренеры — из БД), форма «Пробное занятие» (сохраняется в таблицу «applications»), регистрация и вход.
**Клиент:** покупка абонемента (карта — демо-оплата, или на ресепшене), заморозка/разморозка, запись на занятия и отмена, профиль, смена пароля.
**Тренер:** свои занятия и записавшиеся клиенты.
**Администратор** (`/admin`): обзор и выручка, заявки, клиенты, абонементы (подтверждение оплаты, отмена), тарифы, расписание (с проверкой конфликтов), тренеры, залы.

## Как устроена работа с Access
- Весь SQL написан в «общем» диалекте Access/SQLite: соединения только `INNER/LEFT JOIN` со скобками, без `LIMIT`, `COALESCE`, функций дат (даты считает Python). Проверка: `python tests/lint_access_sql.py`.
- Даты и время хранятся текстом ISO, статусы — короткими текстовыми кодами. Допустимые значения и правило «один живой абонемент у клиента» контролирует код сайта (CHECK и частичные индексы через ODBC в Access недоступны).
- Запись данных идёт через транзакции с блокировкой, чтобы два клиента не заняли последнее место одновременно.

## Файлы
- `app.py` — сайт и кабинет клиента/тренера; `admin.py` — админ-панель; `auth.py` — вход, роли, CSRF
- `logic.py` — бизнес-правила; `db.py` — слой доступа (Access; режим SQLite для тестов)
- `schema_access.sql` — структура таблиц Access; `schema.sql` — та же структура для SQLite (разработка/тесты)
- `init_access.py`, `check_access.py` — создание и проверка базы; `templates/`, `static/` — страницы и стили
- `docs/` — ER-диаграмма, UML (`Спортклуб_UML.mdj`, StarUML), описание предметной области (.docx)
- `tests/` — `python tests/test_site.py` (полный сценарий на временной SQLite-базе), `python tests/lint_access_sql.py`

Фото зала: положите файл `static/img/about.jpg` — оно появится в разделе «О клубе».
Оплата картой — имитация (платёж проводится сразу); для реальных платежей нужен платёжный провайдер.
